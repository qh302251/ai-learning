# 就业竞争力提升路线图（6 个月版）

> 目标：在现有 Agent + LLM 基础上，往**覆盖面最广、当前最缺、且不吃大显卡**的「AI 应用/智能体工程」能力栈补齐，
> 让你能同时适配 **RAG 工程师 / AI Agent 工程师 / 大模型应用开发工程师 / 数据工程师 / 评估工程师** 等岗位。
>
> 硬件：RTX 2060 (6GB VRAM)，无云 GPU → 全部学习内容**不需要显存**，以 API + 框架 + 工程为主。
> 周期：约 3–6 个月，可按 3–4 天/周，每天 3–4 小时。

## 一、定位：为什么学这些（市场依据）

2025–2026 大模型岗位分五梯队，本路线只覆盖你能达到且需求最大的两档：

- **第三梯队（主攻）**：RAG 系统工程师、AI Agent 工程师、大模型应用开发工程师（25-70K，硕士+项目经验）
- **第四梯队（顺带覆盖）**：Prompt 工程师、数据工程师、评估工程师（20-45K）

关键点：
- **AI Agent 工程师是 2025-2026 最热门岗位之一**，JD 明确要求 LangGraph / AutoGen / CrewAI / MCP / 多智能体。
- **RAG 高级加分项**：混合检索、重排、评估、多跳 RAG、Agentic RAG。
- **应用开发岗需求量最大**，要求 FastAPI/Docker/数据库/部署等工程能力。
- 这些**全部 0 显存**，完美匹配你的硬件。

> ⚠️ **明确不学（避免浪费 6 个月）**：大模型预训练 / RLHF / 多模态 / 大规模推理优化（vLLM 源码级）。
> 这些需万卡算力 + 顶会论文，6GB 卡跑不动；除非将来换资源再入。概念懂即可（你已在 learning_plan_llm 覆盖）。

## 三、阶段 1：工程化 RAG 做深（W1-4）★ 复用已有知识库项目

> 把「个人知识库助手」从 demo 升级成**企业级 RAG**，直接变成面试最佳项目。

### 思维导图
```
RAG 工程化
├── 检索
│   ├── 混合检索 Hybrid：BM25(稀疏) + 向量(稠密) 融合(加权 / RRF)
│   ├── 重排 Rerank：cross-encoder / bge-reranker / Cohere Rerank
│   └── 分块 Chunking：递归 / 语义 / 父文档(Parent-Doc) / 元数据过滤
├── 向量库
│   ├── Qdrant / pgvector / Milvus（生产级，替换你的 embedding.json）
│   └── 索引优化（HNSW + 元数据过滤）
├── 文档解析（文档智能）
│   ├── PDF/Word/表格/OCR：unstructured / RapidOCR / 版面分析
│   └── 表格、图表、扫描件处理
├── 评估（RAG 专用）
│   ├── RAGAS：faithfulness / context precision / context recall
│   └── 建测试集（query→golden answer→golden context）
└── 进阶概念（面试加分，能讲清）
    ├── 查询改写 Query Rewrite / HyDE
    ├── 多跳 RAG Multi-hop
    ├── Graph RAG（知识图谱融合）
    ├── Agentic RAG（RAG 作为 Agent 工具）
    └── 幻觉抑制：上下文约束 / 后处理校验 / 引用溯源
```

### 落地清单
- [ ] 用 BM25 + 向量做**混合检索**，用 RRF（Reciprocal Rank Fusion）合并双路结果（替换你现在的并列返回）
- [ ] 引入 cross-encoder **重排**：bi-encoder 粗排 Top-50 → cross-encoder 精排 Top-5
- [ ] **向量库迁移**：从 embedding.json 迁到 Qdrant（或 pgvector，可选 Milvus 了解一下）
- [ ] **解析能力**：支持上传 PDF / Word / 网页，处理表格与扫描件（unstructured + RapidOCR）
- [ ] **RAG 评估**：用 RAGAS 跑 faithfulness / context precision / recall，得到量化指标（这是面试最难被问倒、也最能证明功力的点）
- [ ] 梳理并讲清：查询改写 / HyDE / 多跳 RAG / Graph RAG / Agentic RAG 各自解决什么问题、何时用
- [ ] 在「项目介绍稿」里补一条诚实说明：双路召回 → 现在加了 RRF 融合 + cross-encoder 重排 + RAGAS 评估（把之前"待优化点"变成真本事）

**产出**：一个**装有真实文档、能上传、能回答、有评估指标**的 RAG 服务。

## 四、阶段 2：Agent 框架 + 多智能体（W5-10）★ 最高含金量

> 从"手写 ReAct 循环"升级到"**框架级熟练**"。手写循环证明你懂原理（保留，面试讲），框架证明你能上手生产（新增，面试用）。
> 这是 2025-2026 最热、缺口最大的技能。

### 思维导图
```
Agent 框架
├── LangGraph（重点，最受欢迎）
│   ├── StateGraph 状态机、节点/边、条件分支、循环
│   ├── Streaming（流式）、Human-in-the-loop（人工介入）
│   ├── Checkpointer（会话/记忆持久化，替代你的 memory.json）
│   ├── Tool node 与 ReAct pattern 的标准实现
│   └── 对比你手写的 loop：trade-off 讲清楚
├── 其它框架（了解 + 能对比选型）
│   ├── AutoGen（多 Agent 对话协作）
│   ├── CrewAI（角色分工、任务委派）
│   └── LlamaIndex（Agent 与 RAG 结合）
├── 多 Agent 协作模式
│   ├── Supervisor / Orchestrator（一个主管调度多个 worker）
│   ├── 分工协作（Planner → Executor → Reviewer）
│   ├── 多 Agent 辩论 / 反思（Reflection / Self-critique）
│   └── 工具调用移交（tool handoff）
├── MCP 深化（你已有底子，加深）
│   ├── 完整 Server 端（资源/工具/Prompt）与 Client 端
│   ├── 自动发现与注册（对应你已有 ToolRegistry）
│   └── A2A（Agent-to-Agent）协议概念
└── 低代码平台（国内企业大量使用）
    ├── Dify（RAG + 工作流 + Agent，0 代码也能搭，必会）
    └── Coze 概念了解
```

### 落地清单（第 2 个旗舰项目）
- [ ] 用 **LangGraph** 重写你的知识库助手（或新做一个任务型 Agent），用 StateGraph + Tool node + Checkpointer
- [ ] 加 **Streaming**（打字机流式输出）和一处 **Human-in-the-loop**（高风险操作人工确认——正好补上你 delete_file 的安全短板，把之前面试里承认的"没做防护"变成"现在做了人机确认"）
- [ ] 用 **Dify** 从零搭一个知识库问答 + 一个 Agent 工作流（体现平台上手能力，国内公司简历认可度高）
- [ ] 做一个**多 Agent 分工协作**的 demo：Planner → 检索/写代码/总结 → Reviewer 反思（三 node 协作）
- [ ] 讲清各框架的**选型逻辑**：官方对标问题"什么时候用 LangGraph / AutoGen / CrewAI？"（这个必考，且暴露区分度）
- [ ] 能用文字+图示画出你手写 loop 与 LangGraph 的映射（面试加分）

**产出**：一个 **LangGraph 生产级 Agent**（流式 + 人机确认 + 记忆持久化）+ 一个 **Dify 应用**。

## 五、阶段 3：工程化与落地（W11-16）★ 从 demo 到产品

> 研究/应用岗普遍要求"能把它部署成别人能用的服务"。这块是很多纯算法背景候选人的软肋，你补上就拉开差距。

### 思维导图
```
工程落地
├── 后端：FastAPI
│   ├── async/await、协程、并发
│   ├── SSE / WebSocket（流式输出到前端）
│   ├── Pydantic schema、结构化输出（JSON mode）
│   └── API 设计与版本化
├── 容器：Docker / docker-compose
│   └── 将 Agent/RAG 服务容器化 + 一键编排（服务 + 向量库）
├── 数据库
│   ├── PostgreSQL + pgvector（向量检索一体化）
│   ├── Redis（缓存/会话/限流）
│   └── 了解 MongoDB（文档型）
├── 可观测性
│   ├── LangSmith / LangFuse（Tracing、运行日志、成本监控）
│   └── 自己打 trace + 评估
├── 云部署
│   ├── 阿里云 / 腾讯云轻量服务器，部署一个可访问的网页版
│   └── 了解环境变量、密钥管理
└── CI / 规范
    ├── git 规范（commit / branch / PR）
    ├── 基础 CI（lint + test）概念
    └── 写好 README（中文 + 英文）、架构图、demo 动图
```

### 落地清单
- [ ] 用 **FastAPI** 把阶段2的 Agent 封装成 OpenAI 兼容 API（替换掉你 phase7 的 Flask 方案），并加 **SSE 流式**
- [ ] **Docker** 化：写 Dockerfile + docker-compose，一键起「Agent 服务 + 向量库」
- [ ] 用 **pgvector** 或 Qdrant 存向量，本地也能存储和检索
- [ ] 接入 **LangFuse**（或 LangSmith）做 Tracing，能回放每一次 agent 调用链
- [ ] **部署上线**：一个能被外网访问的 demo 地址（面试能甩链接，差距立现）
- [ ] 项目换成标准的**仓库结构 + 完整 README + architecture 图**，GitHub 主页装点干净

**产出**：一个**能 curl、能流式、能追踪、能外网访问**的完整服务；GitHub 主页 2-3 个漂亮项目。

## 六、阶段 4：评估体系 + 差异化 + 求职（W17-24）★ 可量化、能深答

> 把前面做的全部沉淀成"别人难以复制的**量化结果** + **你独有的差异化**"。

### A. 系统评估体系
- [ ] **Agent 评估**：工具调用准确率 / 任务完成率 / 成本 / 延迟 / 鲁棒性（模拟异常输入）
- [ ] **RAG 评估**：RAGAS 四指标 + 召回率 @k
- [ ] 建一个**评估数据集**（20-50 条黄金问答，含 golden context），跑出 baseline 和优化后的对比
- [ ] 做前后对比表：基础版 vs 混合检索+重排版 → 指标提升 X%（数字最有说服力）
- [ ] LLM-as-Judge 复现 + 说明 fallback（你已在 evaluate 里做过，串联成体系）

### B. 差异化：发挥你的"计算数学硕士"背景
- [ ]（可选加分）做一个**垂直领域 RAG/Agent**：选你熟悉的领域（金融 / 法律 / 学术文献 / **科学计算 / 物理**）搜集数据，用你阶段1-2 的能力搭一个**专业问答助手**
- [ ]（可选加分）结合 PINN / 科学计算背景，做一个 **AI for Science** 相关的轻量应用或科普项目（强调你对"数据质量 + 领域模型"的理解，这是纯工程背景候选人不具备的）
- [ ]（可选）写 1-2 篇**技术博客/知乎**：深度拆解你项目里的一个难点（如 RRF 融合、rerank 取舍、LangGraph 状态机），作为简历/面试的"可深挖点"

### C. 求职输出
- [ ] 更新简历：3 个项目（①知识库助手→升级版 RAG ②LangGraph 多 Agent ③微调部署），每个含**量化指标**
- [ ] 把「面试提词卡」补上新的深挖问题：RAG 评估 / 重排 / 混合检索 / LangGraph 选型 / 多 Agent 协作 / Docker 部署
- [ ] Mock 面试：把阶段2-3 的框架选型、trade-off、遇到问题怎么解决，(这些是最高频深挖题)
- [ ] 作品集：demo 视频 + 可访问链接 + GitHub 主页 README，整理成一份作品集
