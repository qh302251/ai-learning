**🔑 C5.1 的关键认知（面试可讲）**

1. **`Header(...)` 里的 `...` = 必填** → FastAPI **在进你函数之前**就返 **422**。
   但"没带凭证"的语义是 **401（未认证）**，不是 422（参数格式错）→ 必须给默认值把请求放进来。
2. **401 vs 403**：401 = 你还没证明你是谁；403 = 我知道你是谁但你没权限。
3. **`authorization.partition(" ")` 优于 `split`**：没空格时 `split` 只返回 1 个值，解包直接抛异常。
4. **`scheme.lower() != "bearer"`**：HTTP 认证方案名**大小写不敏感**（RFC 7235）。
5. **401 必须带 `WWW-Authenticate: Bearer`**（RFC 要求），否则标准客户端不会弹认证框。
6. **fail-closed**：服务端没配 key 表时要**拒绝一切**，绝不能"配置写错 = 门自动开着"。
7. **审批通道必须和业务通道同级保护**：`/chat/resume` 能替用户**批准危险工具执行**（`write_file` / `delete_file`）——**人工审批防线被绕过，往往不是攻破 `interrupt()`，而是审批接口本身没上锁**。
8. **不要把 key 写进 `index.html`**：`GET /` 是公开的，查看源代码就能拿到 → 等于把钥匙挂在门上。
9. **接口要分级**：`/` 和 `/health` 必须公开（探针不带凭证，加了会导致容器反复重启）；`/chat*` 必须全锁。

### 踩到的坑（新知识，面试可讲）

| 坑 | 现象 | 根因 / 解法 |
|---|---|---|
| `gh auth login` 走不下去 | "The value of GH_TOKEN is being used" | User 级环境变量 **优先级高于存储凭据**，且那个 token 已失效（401）→ 清掉它 |
| git push 握手失败 | `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | git 的 Windows TLS 后端在受限进程里拿不到加密凭据 → `git config http.sslBackend openssl` |
| 凭据助手不认 gh | `could not read Username` | `credential.helper=manager`(GCM) 读不到 gh 存在 keyring 的凭据 → 临时用 `http.extraHeader: Authorization: Basic`，**用完立即 unset** |
| `checkout --orphan` 会不会冲掉暂存区 | 以为要重新 add | **实测：暂存区完整保留**（orphan 分支对空树比较，全部算新增） |
| `git log -S` 会误导 | 它显示 `da82ec2` 动过 `sk-` | `-S` 数的是**字面 `sk-` 出现次数变化**，≠ 含真 key → 必须**逐提交全树 `git grep`** 才准 |
| `Select-Object -First N` 接在**写操作**后 | `$LASTEXITCODE = -1` | 它会**提前终止上游原生进程** → git 写操作不要接这个管道（本次靠 `git fsck` 确认没写坏） |
| 提交作者是 `ai-learning@local` | 提交关联不到 GitHub 头像 | 用 `<用户ID>+<用户名>@users.noreply.github.com` 改绑（不暴露真实邮箱） |
