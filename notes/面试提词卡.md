## 二、RAG（岗位第 1 优先，必问）

**1. 什么是双路召回？**
- 两个独立检索通道：**精确搜索**（字面匹配，搜索包含用户关键词的全文）+ **语义搜索**（向量检索，找意思相近的文档）
- 原理：把文本编码成向量算余弦相似度，语义相近的离得近

**2. 为什么需要双路？**
- 关键词搜索擅长**精确**（编号、代码、专有名词），但"差一个字就搜不到"
- 向量搜索擅长**语义**（不同说法同一意思），但精确匹配差
- 两者互补 → 双路召回 → 去重 → Rerank → Top-N

**3. 你的实现（诚实版）**
- 关键词路：`search_documents` 返回所有含关键词的文档
- 语义路：`semantic_search` 目前只返回最相关 1 段（`rag_tools.py:67`），**没做去重和 Rerank** —— 承认这是待优化点 + 说改进方向

**4. 分块 chunk（你真做过，放心答）**
- `tools/chunk_utils.py`：chunk_size=300 字符、overlap=30 字符
- 短文档没达到 300 就不分；`long.txt` 这种长文档才分了块
- `build_index.py`：对每块单独编码向量存 `embeddings.json`

**5. cross-encoder vs bi-encoder（刚学的，争取答出）**
- **bi-encoder（双塔）**：query 和 doc 分别编码成两个向量算距离。快，可预存 doc 向量 → 适合**第一层海量粗筛**
- **cross-encoder（交叉）**：query 和 doc 拼一起整体算相关性。准，但每个 pair 都要跑 → 适合**第二层精排**
- 标准流程：bi-encoder 粗筛 Top-50 → cross-encoder 精排 Top-5

## 三、数据清洗（岗位职责第 3、4 条，权重第二）

**数据来源**：HuggingFace 开源 `shibing624/alpaca-zh`，中文 Alpaca，约 48818 条，ChatGPT 生成

**三道清洗**：
1. **去 AI 标识**——筛掉"作为AI助手我……"这类模板句，防止模型被教成"机器人复读机"
2. **指令过短过滤**——指令 <5 字没有学习价值，学不到有效的指令→回答映射
3. **回答过短过滤**——回答 <50 字样本没知识含量，还能引导模型偏向输出完整长答案（控制输出长度分布）

**核心目的**：保证训练集都是"高质量的指令→高质量的回答"

**长度分析**（你真做过）：最短 35 / 最长 867 / 平均 171 token
**为什么 max_length=400**：平均 171 已覆盖绝大多数样本，少数超长（如 867）被截断——这是**取舍**，为省显存（6GB）+ 提速（batch 小 + 注意力 O(n²)）。再大只喂不重要长尾，性价比低。
