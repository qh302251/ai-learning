# 项目介绍稿（面试用）

## 一句话
我做了个**个人知识库助手**，基于 ReAct 循环的 Agent，能根据用户问题自主调用工具完成任务。

## 架构（三层）
- **上层**：agent_core — ReAct 循环（Thought → Action → Observation）
- **中间层**：ToolRegistry — 所有工具统一注册、分发，屏蔽底层差异
- **底层**：工具实现 — 本地工具（文件、搜索、记忆）+ MCP Server（calculator、get_weather 等扩展）

## 关键决策
- **RAG 用混合检索**：关键词搜编号精确匹配 + 语义搜防止"差一个字搜不到"
- **MCP 做扩展**：MCP Server 定义工具，Client 自动发现并注册到 ToolRegistry，无需手动对接
- **记忆用 JSON 持久化**：项目规模不大，没必要向量数据库

## 踩过的坑
工具 schema 描述不够清晰 → 模型调错参数 → 在描述里加示例值解决

## 量化指标
- 8 个测试文件，覆盖所有核心模块
- 支持 9 个工具（文件、搜索、记忆、MCP）
- 语义搜索模型：paraphrase-multilingual-MiniLM-L12-v2
